# LX Music 手表版 —— 构建说明（交接文档）

> 更新：2026-10-15
> 成品：`/sdcard/Download/LX Music 手表版 v1.9.1.apk`（arm64-v8a，13MB，已签名）

## 1. 这是什么

从 `lyswhut/lx-music-mobile` v1.9.1（React Native 0.73.11）源码编译的 LX Music，
针对 **410×502dp 表盘**（横竖屏自适应）做的小屏适配版。

- 源码与构建目录：`/root/work/lx/lx-music-mobile-master`
- 包名：`cn.toside.music.mobile`（与官方版相同，签名不同 → 不能覆盖安装官方版，需先卸载）

## 2. 本机（aarch64 容器）构建的最大坑

官方 Android 工具链**只有 x86-64 版本**，本机是 aarch64，因此逐项做了替换：

| 工具 | 处理方式 | 位置 |
|---|---|---|
| aapt2 | x86-64 官方版 + qemu-user 包装 | `/root/work/lx/tools/aapt2/aapt2` |
| hermesc | x86-64 官方版 + qemu-user 包装 | `/root/work/lx/tools/hermesc` |
| clang / clang++ | **改用宿主原生 aarch64 clang-17 交叉编译** | `/root/work/lx/tools/hostclang` |
| ld.lld / llvm-* | 原生 aarch64（lld-17）+ 少量 qemu 包装 | NDK `bin/` 下已改符号链接 |
| qemu-user | Ubuntu ports 的 qemu-user-static | `/usr/bin/qemu-x86_64` |
| x86-64 sysroot | 由 `/sdcard/dsh/构建工具/x86_64-sysroot` 复制而来 | `/root/work/lx/tools/sysroot-x64` |

NDK 目录 `toolchains/llvm/prebuilt/linux-x86_64/bin/` 已被改写：
- `clang*` → `_androidclang`（调原生 clang 交叉编译）
- `llvm-ar` / `llvm-strip` / `llvm-objcopy` 等 → `_x86shim`（qemu 跑真二进制，真身放在 `x86elf/common/`）

## 7. 第三轮：实机照片反馈后的修正（2026-10-16）

用户发了手表实机照片，三个现象：文字仍挤、圆角留白把界面顶出空边、以及希望参考手表应用的界面。

### 7.1 根因：结构尺寸和字号是两套系数，字号调大后行高跟不上

`scaleSizeH/W` 原本返回值里带 `× global.lx.fontSize`（线性），
但列表行高 `ITEM_HEIGHT` 是在模块加载时算一次的**固定值**，
而文字每次渲染都会再乘一遍字号系数。结果字号调到「非常大」时：

- 文字：变小(小屏系数) × 0.93 × 1.3
- 行内三行文字加起来 ≈ 26dp，而行高 ≈ 36~40dp → 只剩几 dp 富余 → 挤在一起

**改法**：结构尺寸跟随字号只按 **平方根** 增长（`× sqrt(fontSize)`）。
这样「非常大」档下结构只涨 ~1.14 倍，不会比文字涨得快；
同时给手表列表行一个 50dp 的下限，并左右各加 6dp 内边距。

### 7.2 圆角留白改成只做上下

原来的 `watchScreenInset` 给整个页面加四周 padding，
等于在圆角外面又套了一圈边——列表左右被顶出空条，界面更挤。

改成 **只加 paddingTop / paddingBottom**：
- 顶栏、底栏躲开圆角即可
- 列表恢复整宽，左右边缘不再有空白条
- 默认值 24 → **16**
- 设置项文案也改成「上下留白（圆角表盘）」

### 7.3 其他

- 竖屏抽屉宽度 70% → **62%**（手表上抽屉一开，内容区只剩 30%，几乎看不见）
- 播放条三个控制按钮在表盘上约 44dp，已达可点下限（44×44）

### 7.4 参考

Wear OS 官方媒体应用设计指南（列表行高、触控目标下限 48dp）：
- https://developer.android.com/design/ui/wear/guides/surfaces/media-apps
- https://developer.android.com/design/ui/wear/guides/patterns/media/controls

本身就不适合表盘，需要按手表习惯重做一版单行列表（只留歌名，选中态展开）。
这一步是界面重构，不是调参。

## 9. 第五轮：修复「改字号后重启闪退」（2026-10-16）

**现象**：在设置里改字体大小 → 退出 → 再进，第一次闪退，第二次才正常。

**根因（我的锅）**：第四轮我把结构尺寸改成 `× Math.sqrt(global.lx.fontSize)`。
但有一部分模块会在 `global.lx.fontSize` 被赋值**之前**就调用 `scaleSizeH/W`
（`StyleSheet` 在模块导入期就求值），此时 `Math.sqrt(undefined) === NaN`，
NaN 进入原生样式 → 安卓直接崩。
第一次崩、第二次好的原因：崩这一次之后运行环境/缓存状态变了，或首启路径与复启路径不同。

**改法**：
- `src/utils/pixelRatio.ts`：新增 `getFontScaleFactor()`，
  `Number(global.lx?.fontSize)` 非有限正数时一律回退 `1`；
  `clampWatchText()` 也加了 `Number.isFinite` 兜底（NaN 时返回 MIN_TEXT_SIZE）
- `src/app.ts`：赋值处做一次归一化，非法值一律写回 `1`
- 顺带修回一处漏改：`MAX_TEXT_SIZE` 之前误留 16，现已恢复为 **20**
  （否则「非常大」档会被压在 16sp，白调了）

**如果还闪退**：让用户进 **设置 → 错误日志** 导出内容，
`utils/log.ts` 把日志写在 `temporaryDirectoryPath + '/error.log'`，
`utils/errorHandle.ts` 的 `setJSExceptionHandler` 会把 fatal 错误的 stack 写进去。

## 10. 第六轮：字号体系重做（2026-10-16）

用户反馈三点：① 「大」这一档看起来没比「标准」大；② 播放页歌词显示不对；③ 底栏向中间移动没生效。

### 10.1 「大」和「标准」看不出差别 —— 根因是双重乘字号 + 中间取整

原来的链路是：`setSpText()` = `getTextSize()` × `global.lx.fontSize`，
而 `getTextSize()` 里**又**乘了一次 `global.lx.fontSize` → 相当于**平方**。
再加上中间有 `Math.floor`，算出来的档位差被吃掉：

```
设计 15、scale 1.5：标准→13，大→13   ← 两档一样大
```

**已重做**（`src/utils/pixelRatio.ts`）：
- 手表上字号缩放改成固定倍率 `WATCH_TEXT_SCALE = 1.22`（不再用面积比例，那个会把正文压到 10sp）
- 用户字号设置**只乘一次**
- 中间不取整，只在最后 `Math.round`，档位差不再被抹掉
- 钳制区间 `[12, 22]sp`（原来是 [12,20] 且 MAX 曾被漏改成 16）
- 预览用同一个函数（去掉多余的 `× useFontSize()`），**所见即所得**

结果（设计字号 13 为例）：标准 16、大 18、更大 20、非常大 21 —— 四档肉眼可辨。
手机端行为完全不变（`textScale` 仍是原来的 `min(sw/375, sh/667, 1.3)`）。

### 10.2 歌词过大

`playDetail.*.style.lrcFontSize` 是「百分比」，默认 150 → 15 设计号，
再乘 1.22 和字号系数后能到 30+，一行歌词撑爆屏幕。

**已改**：`screens/PlayDetail/{Vertical,Horizontal}/Lyric.tsx` 里
`size = isWatch() ? Math.min(lrcFontSize, 110) : lrcFontSize` 再 `/10`，
即表盘上歌词最大按 110% 算（约 13~17sp）。

### 10.3 底栏「没向中间移动」

代码在 **第五轮**（build17 那一版）就已经加了
`PlayerBar/index.tsx` 的 `paddingLeft/Right: 16`。
用户照片拍摄时间早于该版本安装时间，所以看到的是旧包。
这一版（第六轮）包含该改动，装完再确认。

### 10.4 关于「菜单键内移」

`screens/Home/Vertical/Header.tsx` 的菜单键 `marginLeft: isWatch() ? 12 : 0`，
同样是第四轮就加了，第六轮一并包含。

## 11. 第七轮：字号回调 + 防闪退加固（2026-10-16）

用户反馈：① 上一版字全挤在一起；② 改完字号第一次进仍可能闪退；③ 底栏再往中间收；④ 歌词往外偏。

### 11.1 字号回到 1:1（挤是因为我把字放大了）

第六轮把 `WATCH_TEXT_SCALE` 提到 1.22，正文从 13sp 变 16sp，
**但列表行高是按旧字号定的固定值** → 两行文字直接叠在一起。

**已改回 1.0**，只在用户字号设置上做递进（最终 clamp `[12, 20]`）：

| 设计字号 | 标准 | 大 | 更大 | 非常大 |
|---|---|---|---|---|
| 13（歌名） | 13 | 14 | 16 | 17 |
| 11（歌手/时长） | 12 | 12 | 13 | 14 |

配合行高 **50 → 64dp**，两行文字 + 间距约占 40~48dp，留出余量。
比最初那版的 13sp 略大一点（标准档歌名 13sp 而不是 10sp），并且四档肉眼可辨。

### 11.2 闪退加固（这次是从源头堵）

除了上一轮 `pixelRatio` 的取值兜底，这轮把 `global.lx.fontSize` 本身改成
**getter/setter 访问器**（`src/config/globalData.ts`）：
任何写入都会被校验，非法值（undefined / NaN / 负数 / ≥10）一律落回 `1`。

这样即使某处在 `app.ts` 之前就读取字号，也不可能拿到 `NaN`——
`Math.sqrt(NaN)`、样式里的 `NaN` 是之前闪退的直接原因。

另外 `app.ts` 赋值处也做了同样归一化（双保险）。

### 11.3 底栏 / 歌词

- `PlayerBar/index.tsx`：表盘左右内边距 **16 → 24dp**
- `PlayDetail/{Vertical,Horizontal}/Lyric.tsx`：歌词容器在表盘上
  左右内边距 **20 → 40dp**，把歌词往中间收，避免贴圆角
- 歌词字号在表盘上仍按最大 110% 计（约 13~17sp）

## 12. 第八轮：播放页底部被圆角裁掉（2026-10-16）

用户圈出播放页底部：四个小功能键被表盘下缘切掉，进度条/时间也在同一带；另外按钮太小。

### 根因：`ControlBtn` 容器有个按屏高算的 maxHeight，表盘上算出来比按钮还小

```js
const maxHeight = Math.max(winSize.height * 0.11, MIN_SIZE)   // 502*0.11 = 55
```
容器自身 `paddingVertical: 22 × scaleSizeH(缩放) ≈ 22 → 44dp`，
55 − 44 = 11dp 根本没地方放按钮 → 上下都被裁。
再加上播放页整体靠屏幕最底部，圆角正好切在这里。

已用**与评论接口完全相同的调用链**在 Node 里自测通过（网易那几个 key 全部编码正确、

## 24. 第二十轮：审查后发现的三个根因（2026-10-17）

用户要求「多审查、多点点、把虚拟屏弄小」。审查中发现：

### 24.1 【根因一】结构尺寸在表盘上被压成 0.67 倍

`scaleSizeH/W` 的结果是 `设计值 × scale × uiScale / pixelRatio`。
在表盘上算出来：

| 元素 | 设计 | 表盘实际 |
|---|---|---|
| 列表行高 | 54dp | **36dp** |
| 图标 | 18dp | **12dp** |
| 按钮 | 36dp | **24dp** |

而文字是 1.22 倍放大的 → **字比容器大**，所以文字下半被裁、按钮小到点不中。
**这就是「按钮点不了 + 字体缺失」的共同根因。**

修复：表盘上 `scale = pixelRatio × (√(屏占比) / uiScale) × 1.05`，
让结构尺寸回到设计尺寸量级；字号倍率同步降为 **1.0**。

### 24.2 【根因二】手表判定把方形表漏掉

原判据 `短边 < 460 且对角 < 660`，会漏掉 **480x480、520x520** 这类方形表
（它们的短边 ≥460）。被漏掉时走的是**手机版界面** —— 字小、被裁、按钮点不中。

新判据：`短边 ≤ 540 且对角 ≤ 820`，或 `短边 ≤ 540 且长短边比 ≤ 1.25`。
验算：410x502 ✅、466x466 ✅、480x480 ✅、520x520 ✅；
手机 393x852 ❌、平板 1280x800 ❌（仍走原界面）。

### 24.3 【兜底】新增「强制使用手表界面」开关

设置 → 基础 → **强制使用手表界面**。
自动识别在冷门表型/第三方 ROM 上仍可能不准，这个开关可以直接强制。

### 24.4 虚拟屏测试环境的教训

在虚拟屏上跑时发现 App 的窗口只有 **274×280dp**（被系统塞进 freeform 小窗），
而显示区是 636×1400px。诊断文件里能直接看到这一点。

**教训**：`Dimensions.get('window')` 不一定是整块屏，
在 freeform/分屏下会小很多；表盘布局必须按**窗口**而不是按**屏幕**算尺寸
（当前实现已按窗口算，行为正确）。

## 53. 第四十九轮：界面形态改为「自动 / 手机版 / 手表版」（2026-10-18）

| 选项 | 行为 |
|---|---|
